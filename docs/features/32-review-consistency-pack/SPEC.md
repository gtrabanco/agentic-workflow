## Goal

Make the review pack obey **one owner per rule and one scale per concept**, so
a weak executor never has to arbitrate between contradicting texts: `fold-findings`
becomes the sole, cited owner of the `folded: no → yes` flip;
`review-implementation/references/CLASSIFY.md` becomes the single owner of a
canonical severity conversion table covering every scale the pack emits;
blocking stops being a severity opinion and becomes a **derived gate** — a
finding blocks only when the reviewer cites which single-owner source fails;
a **gate-run receipt** (`GATE-RAN | HEAD <sha> | <cmds> | exit <code>`) lets
any skill reuse a green gate run at the identical head instead of re-running
the same gate up to 4× per unit; and four one-line contradictions (NRS
optionality, triage modes, roadmap-row ownership, `audit-pr`'s gate scale) are
reconciled. Ships the grouped bug fixes (`audit-docs` count/severity bugs,
`product-audit` parallel vocabulary) the issue deliberately carries.

### Context

The workflow's contract texts already declare single owners (`ledger-ownership@1`
in `pre-execution-review/references/LEDGERS.md` is the machine-read map), but
prose written before and after the map still contradicts it, and several
concepts still have parallel local vocabularies:

1. **Three surfaces claim the folded flip.** `PERSIST_AND_DECIDE.md` says
   "`execute-phase`'s fold cycle is the only step that ever flips it to
   `yes`"; `FOLDING.md` says the fold cycle owns the flip ("the one and only
   ledger state transition"); `fold-findings/SKILL.md` says "this skill only
   flips". The machine map (`ledger-ownership@1`) names exactly one annotator:
   `fold-findings:folded-flag`. `LEDGERS.md`'s own prose ("So `fold-findings`
   flips only the `folded:` flag `triage-issue` gives it") contradicts its own
   table, whose `review-findings` rows are written by `review-change`,
   `audit-pr`, and `triage-issue` alike. A weak model reading any two of these
   surfaces must guess.
2. **Severity scales are local and partly buggy.** The ledger scale is
   `high | med | low` (CLASSIFY.md); `audit-docs` defines **14 checks** but its
   report contract emits `Checks run: <n>/13`, and one finding prose uses a
   `MEDIUM` severity its legend does not define; `product-audit` classifies
   with a parallel `fix-now | postpone | tradeoff` vocabulary where the pack's
   closed class set is `fix-now | replan-in-unit | decision-required |
   proposal | ignore`. Feature 31 will add a planning scale
   (`info|low|medium|high|critical`). No conversion table exists, so each
   consumer converts ad hoc.
3. **Blocking is a severity opinion.** Nothing ties "this finding blocks" to a
   checkable source; an LLM reviewer's severity confidence is the de-facto gate.
   External evidence (E-11, E-12) shows LLM reviewers systematically
   overcorrect — and that detailed, explanation-demanding prompts increase
   misjudgment — so a reviewer's confidence is exactly the wrong authority for
   "blocks vs doesn't".
4. **The gate is re-run for no reason.** Several skills mandate running the
   project's gate per turn; a unit pays up to 4 identical gate executions per
   cycle. A SHA-bound "gate ran green here" mark — the same binding pattern as
   `review-mark@1` — lets any skill reuse the result at the identical head and
   forces a re-run the moment the head changes.
5. **Four one-line contradictions** send mixed signals: `workflow-status`
   treats a *missing* NRS ledger as a blocker (script `NRS_BLOCKING` set
   includes `missing`) although NRS is optional everywhere
   (`EXECUTION_CONTRACT.md` already says "record `n/a: no normalized
   repository state`; NRS is optional"); `review-change`'s relationships name
   only one of `triage-issue`'s three modes; `plan-feature`'s roadmap wording
   blurs verify-vs-write against `ledger-ownership@1` (scaffold is the sole
   `defined → planned` writer); `audit-pr` emits a gate scale
   `blocker / warning / n-a` whose `warning` exists nowhere else.

Issue #172 groups these deliberately — they are one consistency sweep with
several genuine bug fixes, not five micro-features. The 2026-09-07 amendment
adds one obligation: the gate-run receipt's format carries **extensible digest
slots** from day one so feature 35 can add a scope manifest without a format
migration.

### Business goals

- **Token economy of unattended delivery.** The gate-run receipt removes the
  largest purely-mechanical recurring cost per unit: re-running an unchanged
  gate 4× per cycle. Consistent wording removes the re-reading and
  re-arbitration tax a weak model pays every time two surfaces disagree.
- **Weak-model safety.** Blocking becomes a citation-backed table lookup, not
  a judgment call — the same "separate possible risk from confirmed violation"
  direction as the external evidence the issue cites. A model can verify a
  citation; it cannot reliably calibrate severity confidence.
- **Review-loop convergence.** The derived blocking gate is the substrate
  feature 50 (`review-loop-convergence`) composes with its materiality bar;
  shipping it now makes that feature smaller and safer.

### Scope

#### In scope

- **IS-1 — Sole fold-flag flipper.** `fold-findings` is the only writer of
  `folded: no → yes`, owned by `ledger-ownership@1`
  (`fold-findings:folded-flag`). The two contradicting texts
  (`PERSIST_AND_DECIDE.md`, `FOLDING.md`) are corrected to cite the map, and
  `LEDGERS.md`'s prose is corrected to agree with its own table. A scan of
  `docs/workflow/` tutorials for restated flip claims verifies no contradicting
  restatement survives (dated run-log history in `GOLDEN_FIXTURE.md` is a
  record of past runs, not contract text — not edited).
- **IS-2 — Canonical severity conversion table.** One table, owned by
  `review-implementation/references/CLASSIFY.md` (the declared single
  classifier), mapping every severity scale the pack emits:
  the ledger scale `high | med | low`; feature 31's planning scale
  `info | low | medium | high | critical` (row lands with/after 31); and
  `audit-docs`' local `high | low`. The issue's claimed finder scale
  `critical | major | minor` does **not** exist anywhere in the repo at
  authoring time (E-09) — see D32-2. Bug fixes in the same sweep:
  `audit-docs` emits the true check count (`<n>/14`) and drops the phantom
  `MEDIUM` (its legend allows `high | low` only); `product-audit` classifies
  by referencing the closed class set instead of `postpone/tradeoff`.
- **IS-3 — Derived blocking gate.** One rule in `CLASSIFY.md` (D10's verdict
  rule unchanged): *a finding blocks only when the reviewer cites which
  single-owner source fails — (a) an ACCEPTANCE criterion unverified/failed,
  (b) an obligation row ≠ `verified`/`n-a`, (c) the gate red at head, (d) an
  open confirmed `fix-now` row. No citation → report-note or proposal, never
  blocking.* Blocking becomes a table lookup over cited sources, not a
  severity opinion. Pinned by the discipline test.
- **IS-4 — Gate-run receipt.** A `GATE-RAN | HEAD <sha> | <cmds> | exit <code>`
  mark recorded by whoever runs the project's gate, appended to the unit's
  ledger (home ledger + single writer fixed by a `ledger-ownership@1` map row
  added in the same change). Any skill may consume a green run **only at the
  identical HEAD**; a changed head ⇒ re-run. Extensible digest slots from day
  one: fields after `HEAD` are additive; consumers ignore unknown trailing
  fields; a trailing `manifest <sha>` slot is reserved for feature 35. Ends
  the 4× mandated gate re-execution per unit without weakening freshness;
  `audit-pr` keeps consuming CI as today.
- **IS-5 — Contradiction fixes (one line each).**
  (a) NRS optional everywhere: `workflow-status` degrades the *missing-ledger*
  case from blocker to a machine-readable substrate notice (`draft`,
  `contradicted`, `resolved` stay blocking — only `missing` degrades);
  (b) `review-change`'s relationships name `triage-issue`'s three modes
  (proposals / audit findings / `--prioritize-now`);
  (c) `plan-feature` verifies-not-writes the roadmap row (scaffold stays the
  sole `defined → planned` writer);
  (d) `audit-pr`'s gate-result scale aligns to `pass / blocker / n-a` (the
  `warning` value is removed).
- **IS-6 — Bibliography obligation.** When this feature's PR merges, the
  arXiv:2603.00539 entry is appended to `README.md` under a bottom
  `## References` section (create if absent; dedupe against entries other
  features added; cite as printed in the issue). Never cited in README before
  the feature ships.
- **IS-7 — Bumps and pins.** Minor version bumps to every touched skill;
  discipline-test pins are updated to assert the new contracts and never
  weakened.

#### Out of scope / non-goals

- **No big-bang severity unification** — the closed per-surface vocabularies
  stay; only the conversion table is canonical (issue non-goal).
- **No new `blocking:` field on findings** — it would duplicate the `fix-now`
  class (issue non-goal); blocking stays derived from citations.
- **No schema-package change** — the GATE-RAN mark is an appended text mark,
  not a schema contract; the missing-ledger substrate notice reuses the
  sensor's existing output vocabulary (`packages/agentic-workflow-schema`
  untouched, regression-only).
- **No planning-side loop-policy changes** — materiality floor, two-cycle cap,
  and wording-only determination belong to feature 31; this feature only adds
  the planning-scale row to the conversion table once 31's vocabulary exists.
- **No turn-contract migration** — bespoke contract text reconciliation is
  feature 33 (`turn-contract-single-owner`).
- **No scoped affecting-path manifest** — the CLI and manifest digests are
  feature 35; here only the trailing `manifest` slot of GATE-RAN is reserved.
- **No bilingual siblings** — English-only interim (AD-002 / F011): no
  `.es.md` files are created or updated.
- **No `template/` change** — the GATE-RAN mark is recorded output, not a
  ledger convention the template mirrors (same ruling as feature 30's
  receipt).
- **No re-wording of `execute-phase`'s NRS clause** — `EXECUTION_CONTRACT.md`
  already records NRS as optional at authoring HEAD (E-14); that surface gets
  a regression check only.
