**S1 — the order: apply #703 to this repository, inline.**
> Apply to this repository: issue #703

**S2 — the skill, its whole job, and its two names.**
> A user-invocable skill — **`/agentic-workflow-doctor`** (alias **`/aw-doctor`**) — whose whole job is: mine the ceremony failures that have accumulated in THIS project so far, triage them all in one pass (discard vs report), produce one complete anonymized report, and route it upstream — adding evidence to an existing agentic-workflow issue when one already covers the defect family, creating a new one only when none does. Read-only about the consumer's code; runs ONLY on the user's explicit initiative.

**S3 — the standing constraint: every mechanical step is a runner subcommand.**
> **Standing constraint (owner directive, added 2026-11-23): every mechanical step on this list is CODE — a runner subcommand shipped by the crate's CLI (the #553/#603 universal CLI family: registry, `--help` parity, failure feedback with candidates, stderr-only feedback channel) and documented like every other shipped command — never free-form agent scripting.** […] A step that cannot yet be a CLI subcommand is not a step: it is a scoped gap to file, not shell improvisation in a consumer session. Documentation ships with the commands (README/usage rows in the CLI contract, the normative-surface registration for any fixed grammar they read or emit).

**S4 — collect/history mining, over the project's own durable record.**
> **History mining** (the plus): scan `docs/LOGS.md` + unit docs for ceremony-failure markers — gate failures by name, exit codes, stale/refused receipts, `E-f0`-style evidence failures, review-cycle counts above a threshold, labels like `blocked by a receipt`, fold rounds over budget. The corpus is user-generated by construction (every session logs itself), which is the dataset nobody else has.

**S5 — collect/live battery: fixed commands with captured exit codes.**
> **Live battery** — fixed commands with captured exit codes: installed skill set + pin/train versions, runner `doctor`, the unit slug + PR + issue numbers the user names, verdict receipts/markers in play with SHAs and scope digests (`gate-receipt verify`, `review-receipt verify`, the PR's receipt comments), the failing runner commands and stderr tails, ceremony tier + config profile. Once #698's typed receipts land, the battery reads them directly instead of mining session prose.

**S6 — triage: a fixed rubric the model applies, never a judgment.**
> **Triage** — a fixed rubric the model applies, not a judgment: each finding class gets `discard` (operator error, env-specific, already covered upstream, one-off human novelty) or `report` (reproducible defect, contract-vs-behavior mismatch, cross-project recurrence); `report` rows cite their evidence lines. The rubric is data in the skill (a table), so the small model classifies by lookup, never by weighing.

**S7 — anonymize: one fixed redaction profile.**
> **Anonymize** — a fixed redaction profile: allowlist the field classes above; deny repo content, file trees, paths beyond the unit-doc slug family, user names, e-mails, issue titles beyond numbers, any secret-shaped value (reuse the secret-scan shape); normalize paths to slug anchors; keep SHAs and digests.

**S8 — route: search upstream, append or draft, consent before filing.**
> **Route** — search the upstream tracker for each report-class family (check names + defect shape; the known corpus #170, #301, #260, #698, #701, #702 first); per finding, either append dated evidence to the matched issue (with consent) or draft a new one. The draft is shown to the user; filing happens only with explicit user consent. Every step reports through stderr; the bundle file is the stdout receipt.

**S9 — read-only, and only on the user's initiative.**
> No step mutates the consumer repository (read-only profile), and the skill never runs as a side effect of another workflow step — the #698 advisory may SUGGEST running it; the invocation stays the user's.

**S10 — the acceptance shape: one invocation, one maintainer-actionable bundle.**
> From "my reviews keep blocking each other and I don't know why" to a triaged, anonymized, upstream-routed report in one invocation — including a batch pass over a project that has run the workflow for months; a maintainer can act on the bundle without access to the consumer repo; no rule survives the anonymization of which repository produced it beyond the user's own decision to name it.

**S11 — the battery consumes the tool doctor's envelope as-is.**
> **1 — the battery consumes the doctor envelope, so it inherits every check for free.** The collect layer's "live battery" takes the tool-doctor's envelope as-is (`tool-doctor-envelope@1`, carrier row in GATE_INVENTORY).
