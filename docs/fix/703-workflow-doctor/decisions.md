# 703 — workflow-doctor · decisions

Each row is a decision this unit's plan rests on (`decision-scope@1`: every row
here is `unit-only` — the rubric's and the redaction profile's cross-cutting
halves live in the skill reference, their one owner, where a future unit reads
them).

| id | decision | scope | ground |
|---|---|---|---|
| D1 | **The unit is applied inline** against the frozen ledgers: the §5 freeze is the plan, `execute-phase`'s review pack, `audit-pr` and the fold cycle are not run on it, and the repository's deterministic gates are the only ceremony. The operator is the external verifier. | unit-only | the operator's order, quoted verbatim as `## Log` L2; `IR3`/`IR4` still bind (no test is weakened to pass, the suite lands red first) |
| D2 | **The alias is a second skill directory, not a second name on one directory.** This repository has no skill-alias carrier (a skill's command name is its frontmatter `name:`, and `alias-coverage.test.mjs` pins exactly one command per user-invocable skill), so `/agentic-workflow-doctor` owns the body and `skills/aw-doctor/` is a five-line pointer that names its owner and restates no rule. The alternative — renaming the single skill to the short form — was rejected because the issue names the long form the skill and the short form the alias; the pointer delivers both commands on every host the `skills` CLI installs into. | unit-only | S2; `PE-007`; `IR11` (a repetition names its owner) |
| D3 | **The marker set is built on declared line kinds, never on prose matching.** A row is emitted only from a shape a machine already owns: a `## Log` `G`/`E` line whose body records a non-zero exit, an `R` line carrying a review verdict, an `F`-per-unit count over the correction budget, or a `journal-corpus` row (correction, refuted finding, rework). The measured corpus (`PE-001`, `PE-002`) is why: a lexical probe over the same tree matched 1,510 `phase-lint` mentions, almost all of them the unit that built phase-lint, which is the noise a small model must never be handed. | unit-only | S4, S14a; `PE-001`, `PE-003`, `PE-004`, `PE-018` |
| D4 | **The miner never decides.** A non-zero-exit line includes the red-first receipt a green unit is *required* to record, so the miner emits a candidate and the rubric's `discard` column is where an expected red leaves the report. The thresholds it does apply are aggregates of the same record — `--fold-budget 2` and `--cycle-budget 2`, the correction budget's own default — and they are flags, so a project can state its own. | unit-only | S4, S6; `PE-001`, `PE-018` |
| D5 | **Triage is per marker kind, and the model cites representative rows.** The closed rubric has one row per marker kind (eight), each with its two columns; the triage file names, per class, a verdict, a reason from the closed set, and one to five `W<n>` ids as evidence. A class that cites no row is refused, and rows no class claims are reported as an `unclassified` count — never bucketed by guess. This is what keeps a 400-row corpus a small model's eight-row lookup instead of a weighing. | unit-only | S6, S10; `PE-019` |
| D6 | **The battery reads the ceremony tier** (`S14b`'s open question, answered): the profile comes from the guide's `ceremony-profile@1` block through its reader and the tier from the named unit's `## Risk tier` through `recordedTier`. S5 lists "ceremony tier + config profile" as battery content, so leaving it to the rubric would drop an input the issue names. | unit-only | S5, S14b; `PE-015` |
| D7 | **No schema package moves.** The four closed sets (marker kinds, verdicts, discard reasons, report reasons) are runner-internal: the grammar blocks that declare them carry `machine: n/a`, exactly as `journal-corpus-grammar` does, so no published contract names them and `vocabulary-residency@1`'s `runner-internal` case applies. A future unit that publishes a vocabulary moves it to the schema package in that change, never a copy. | unit-only | S3; `AGENTS.md` §"Normative surfaces"; `docs/architecture/ARCHITECTURAL_INVARIANTS.md` `vocabulary-residency@1` |
| D8 | **The route drives the shipped guarded transport, and `publish` is the only write.** Candidate discovery reads numbers only through `createGhTransport().readList` (`search/issues`), every candidate's content is re-read through `readForge` so no third-party field escapes the guard, and the one write path is `publish` behind `--yes`. A non-GitHub upstream refuses by name (`unsupported-upstream-forge`) instead of guessing a CLI, and the crate's PR-only `comment()` is not bent into an issue writer. | unit-only | S8, S9, S13; `PE-006`, `PE-020`, `PE-021` |
| D9 | **The bundle's anchors are slugs and log tokens; the `file:line` never leaves the process.** A row carries its internal anchor for the miner and the test, and the bundle prints `unit:<slug>` + `lg:<token>` (or `jn:<ref>`). The model-authored fields are the only free text, so they are the only fields the profile must scan; a secret-shaped value in any field refuses the whole bundle (exit 2, no bytes) rather than printing a partial receipt. | unit-only | S7, S10, S12; `PE-012` |
| D10 | **Two output shapes, one owner each.** The machine receipts (`mine`, `battery`, `--json`) are JSON; the bundle is markdown because its destination is a forge issue and its reader is a maintainer without the consumer's tree. The bundle's first line carries the contract id and the fixed field order the README's `workflow-doctor-bundle@1` block declares, so the prose and the renderer cannot drift. | unit-only | S8, S10; `## Tasks` P4 |
