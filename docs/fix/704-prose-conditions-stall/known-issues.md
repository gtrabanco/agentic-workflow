# 704 — prose-conditions-stall · known issues

Residuals this unit knowingly leaves open, each with the condition that
re-triggers it. A row here is a disclosure, never an excuse: nothing on this page
is a delivery obligation of this unit.

| id | observation | re-trigger | affects |
|---|---|---|---|
| KI-1 | The `stalled-when` column of the `delivery-condition@1` block states, in prose, the rule `judgeCondition` implements; the suite pins the block's *kinds and phrasings* against `CONDITION_PATTERNS` in both directions, but the rule sentence itself is a mirror no gate recomputes. A change to one side alone would be caught only by the per-kind cases, and not every kind's rule has a dedicated case. | the first change to a family's state rule, or the next unit that adds a sixth kind | the doc↔code mirror only; the guard and the sweep behave as `judgeCondition` says |
| KI-2 | The comment carrier is a `gh search issues --match comments` read per phrasing stem, so a condition written in a dialect the forge search tokenizes differently (a phrase split across a line break, or a language the table does not cover) is not found. The body carrier still runs for every issue, and the read degrades by name (`unavailable-forge-comment-scan-…`) instead of failing silently. | the first conditional record the sweep is expected to find and does not, or a forge whose search stops matching comments | the sweep's recall only; it never reports a false stall from a missed read |
| KI-3 | The `condition-uncarried` advisory is a pattern match without a semantic model, so a sentence that merely *mentions* a delivery vocabulary ("the tests are covered by the runner suite") can be reported as an advisory. Advisories never fail a run and never block a close, so the cost is noise in the block, not a false gate. | an advisory volume that makes the summary unreadable in the scheduled run | the sweep's signal-to-noise, never its verdict |
| KI-4 | Closing an issue through a PR merge (`Closes #n`) is not guarded: the forge closes it, and no pre-close hook exists to run `--close-check`. The scheduled sweep is the backstop for that path, exactly as S6 words it ("something scheduled notices at worst within one sweep"). | a forge or host that grows a pre-close hook, or a unit that wires the guard into the merge gate | the close-time half only; the sweep still re-judges the condition afterwards |
| KI-5 | The roadmap corpus reads the `## Fixes` table only. A `## Features` row carrying a condition is not judged, because that table's status vocabulary and column meanings differ and the unit had no measured need for it (`decisions.md` D2). | the first feature row that records a delivery condition | the roadmap half of the sweep only; issue bodies are always read |
