# 727 — machine-ledger-commits · decisions

Each row is an owner decision this unit's plan rests on (`decision-scope@1`).
`D1`–`D3` are `cross-unit`: their statement is promoted to the owner doc the row
names, and this folder only links it.

| id | decision | scope | ground |
|---|---|---|---|
| D1 | **The class, one owner, three agreeing sources.** A path whose writer is machinery belongs to the *machine-owned ledger* class; the machine statement is `MACHINE_LEDGER_CLASSES` in `packages/agentic-workflow/src/machine-ledger/index.mjs`, its prose projection is `skills/pre-execution-review/references/LEDGERS.md` (`machine-ledger-commit@1`), and `.gitattributes`' `agentic-shared-*` lines are the merge-class source. A parity suite refuses a one-sided addition, so no fourth list can appear. | cross-unit → `skills/pre-execution-review/references/LEDGERS.md` | S5, S6; `PE-001`, `PE-009`; `IR1` |
| D2 | **A commit happens in a zone, never per file.** `zone: auto` means the machinery that writes the bytes also commits them (telemetry, session log, journal fragments) — those are swept by the teardown, `session-close`, `reconstruct write` and the gate prelude. `zone: writer-step` means the step that writes the row commits it (roadmap rows, unit-doc ledgers): machinery annotates, the writer commits, and the review exempts the row meanwhile. The zone is the single commit point the policy states per class. | cross-unit → `skills/pre-execution-review/references/LEDGERS.md` | S6; the issue's table; `PE-002` |
| D3 | **Box 5 exempts the class, never a file pattern a caller invents.** The dirty-tree verdict filters exactly the paths the class declares and nothing else; `ahead-of-remote` is untouched, so an exempt row can never excuse an unpublished commit. | cross-unit → `skills/orchestration-envelope/references/TURN_CONTRACT.md` + `packages/agentic-workflow/src/turn-contract.mjs` | S5; `PE-003` |
| D4 | **The pi extension spawns the crate command instead of re-implementing git.** One implementation (`telemetry commit`) answers every caller: the teardown, the skills-only close, the reconstruction. A second git implementation inside the extension would be a second owner of the lock and the subject. | unit-only | S2, S3; `PE-002`, `PE-005`, `PE-006` |
| D5 | **The commit is a pathspec commit behind a lock.** `git add -- <paths>` then `git commit -m <subject> -- <paths>` commits the named paths' working-tree state and leaves a foreign staged file in the index; the lock (exclusive create, bounded wait, stale takeover) serialises concurrent sessions, and a locked or clean class is a typed no-op, never a retry loop that blocks a teardown. | unit-only | S2; `PE-002`; `IR2` (the commit never rewrites history) |
| D6 | **The gate's commit is a prelude, not a pool step.** Steps are dispatched concurrently, so a step that commits would race the suites reading the same bytes and the `log-immutability` range reader. The prelude runs sequentially before the pool, is `--only`-selectable and `--dry-run`-visible like any other step, and an unknown class there is a no-op receipt. | unit-only | S4; `PE-007` |
| D7 | **`needs-triage` gains an exit beside its application.** The label vocabulary (`LABELS.md`) states the removal rule and its loud-on-failure clause; `ISSUE_PROCESS.md`'s classify step runs it after a published verdict, `remove` included. `human-revision-needed` is untouched (`IR5`). | unit-only | S7; `PE-008` |
| D8 | **No new schema vocabulary.** The class is consumed by code (paths and subjects), never by a skill grammar token by token, so publishing it as a schema const would add a vocabulary nothing imports as a vocabulary. The ledger's block is prose the parity suite reads; the normative-surface row declares it with `machine | n/a`. | unit-only | S6; `PE-009`, `PE-011`; the `normative-surfaces@1` grammar |
