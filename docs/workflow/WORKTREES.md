# Worktrees — where they live, how they are made, how they are recovered

> Deep reference for the guide's `## Deep references` index. The guide keeps the
> law (`## Inviolable rules` → `IR8`) and this page keeps the procedure, so a
> session that never creates a worktree pays nothing for it.

## Where they live

This repo uses git worktrees under `.worktrees/<flat-name>` at the repository
root (gitignored). The path must stay **inside the repository tree** — Serena and
other MCPs detect worktrees as separate project paths and break when worktrees
live outside the repo tree — but **never inside `.git/worktrees/`**.

⚠️ **CRITICAL: `.git/worktrees/` is git's private worktree-administration
namespace, not a place for working trees.** `git worktree prune` deletes any
container directory under it **recursively — with the working tree and its
uncommitted work inside it** — exit 0, no warning. A path like
`.git/worktrees/fix/493-x` also collides with git's basename-named admin dirs
(`feat/493-x` and `fix/493-x` become `493-x` and `493-x1`), leaving an
admin-to-tree mapping no tool can follow. The guard (`scripts/worktree-guard.mjs`)
flags any worktree under `.git/worktrees/` as `ADMIN_NAMESPACE`. **Never create,
move or restore a worktree into `.git/worktrees/`.**

## Branch name and flat worktree name

Branch names follow the unit kind:

| Unit kind | Branch format |
|---|---|
| Feature | `feat/<issue-number>-<topic-slug>` |
| Fix | `fix/<issue-number>-<topic-slug>` |

Examples: `feat/432-model-memory-tier-0`, `fix/429-log-session-extension`.

If a remote branch already exists on the correct name (`origin/feat/…`), use it as
the source and preserve its full history (do not create a new branch from `main`
unless the issue is brand new with no commits yet).

The worktree directory is the branch name with `/` replaced by `-` — one flat
leaf, no nested slash:

| Branch | Worktree path |
|---|---|
| `feat/432-model-memory` | `.worktrees/feat-432-model-memory` |
| `fix/429-log-session-extension` | `.worktrees/fix-429-log-session-extension` |

The flat leaf keeps git's admin dir (named after the basename) 1:1 with the
working tree — no basename collisions, ever.

## The steps, in order

When asked to create a worktree for an issue or branch, follow these steps **in
order** — they are not optional and have no shortcuts.

1. **Determine the branch name** (the table above), and reuse `origin/<branch>`
   when it exists.
2. **Derive the flat worktree name** (the second table above).
3. **Remove the local branch if it exists.** The worktree creation recreates it,
   and git refuses a branch that is already there:

   ```bash
   git branch -D <branch-name> 2>/dev/null
   ```

4. **Create the worktree (one step).**

   ```bash
   git worktree add -b <branch-name> .worktrees/<flat-name> <branch-name-or-sha>
   ```

   Or, when the branch already exists (a remote branch from step 1):

   ```bash
   git worktree add .worktrees/<flat-name> <branch-name>
   ```

   `.worktrees/` is gitignored, so the checkout never shows up in `git status`.
   **Never** use `/tmp` or any path outside the repo, and **never** a path under
   `.git/` — see the namespace warning above. For a new issue with no remote
   branch yet, `-b <branch-name>` creates the branch from the current HEAD (run it
   from `main` when the unit must start there).

5. **Copy Serena configuration.** Every worktree must have a working
   `.serena/project.yml` (the one Serena readability gate in
   `packages/pi-agentic-workflow/src/routing/serena-readiness.ts` parses to
   announce `language_servers`). Copy from the repo root:

   ```bash
   cp -n .serena/project.yml .worktrees/<flat-name>/.serena/project.yml
   cp -n .serena/project.local.yml .worktrees/<flat-name>/.serena/project.local.yml
   ```

   The `.project.yml` file is gitignored and gets regenerated by `init-workspace`,
   but copying it ensures Serena starts with language servers from the first
   second.

6. **Verify.**

   ```bash
   git worktree list  # should show the new entry under .worktrees/
   git log -1         # should show the correct branch head
   ```

## Common failure modes

- Worktree created at `/tmp/...` → Serena fails to detect it.
- Worktree created under `.git/worktrees/` → `git worktree prune` destroys it
  (and every sibling tree in the same container) silently; move it out with
  `git worktree move <path> .worktrees/<flat-name>` — never prune it.
- Branch deleted then re-created from `main` → loses all remote history.
- Missing `.serena/project.yml` copy → Serena reports "no language_servers".
- `fatal: '<path>' is a missing but already registered worktree` → the worktree's
  directory is gone; recover with `git worktree repair` or remove the stale entry
  with `git worktree remove <path>` / `git worktree prune`. **Prune only removes
  registrations whose directories are already gone** — never run it to "fix" a
  worktree that still exists on disk, and never point a recovery at a path under
  `.git/worktrees/`.

## Removal

When a worktree is no longer needed, remove it **before** deleting the branch:

```bash
git worktree remove .worktrees/<flat-name>
git branch -D <branch-name>
```
